# Codex 인계 — 1·2화 검토와 연기 지시

## 현재 결과와 범위

사용자의 최신 요청은 1·2화 문제점, 모든 대사의 연기, 윤수 발화 포인트와 문장 적합성 검토다. 이번에 작성한 것은 별도 검토·음성 연기 자료다. 기존 완성 영상·음원·정본·S02 설계를 수정하거나 합성하지 않았다. 이전 AGENTS의 1·2화 제외는 과거 3~5화 작업 범위였다. 최신 AGENTS 상단의 후속 범위를 읽는다.

기준 본편은 **S01 26개 + S02 102개 = 128개**다. 이 중 정본은 S01 26개/S02 21개이고, S02에는 이미 작성되어 있던 NEW81개가 있다. 이번에 81개를 새로 만든 것이 아니다. 기본 모델은 I01 1개 + S02 10개 =11개이며 실제 생성된 오디오가 아니다. 16개 참여에는 S01의 선택5곳이 포함되므로 16개를 모두 필수 발화나 기본 모델 수로 바꾸지 않는다.

## 읽는 순서

1. 이 폴더 `README.md`, `YOONSU_SPEAKING_POINTS.md`, `CORRECTION_PROPOSALS.json`.
2. 기존 `docs/series_v2/VOICE_PERFORMANCE_BIBLE_V2_1.md/.json`과 `assets/voice_refs/v6/VOICE_REFERENCES.json`.
3. `S01_VOICE_DIRECTION_PLAN.json`, `S02_VOICE_DIRECTION_PLAN.json` 및 같은 내용의 사람용 `ACTING_SCRIPT.md`.
4. 실제 구현을 맡으면 현재 엔진·플레이어 코드를 먼저 확인한다. 이번에 확보하지 못한 실행 파일의 기능을 있다고도 없다고도 단정하지 않는다.

## 음성 작업의 필드 계약

|필드|용도|
|---|---|
|`spoken_text`|유일하게 읽는 영어 대사|
|`speaker`, `voice_direction.profile_id`|캐릭터와 고정 음색 식별|
|`approved_reference`|기존 승인 MP3 경로와 SHA. 다른 목소리로 대체하지 않음|
|`voice_direction.listener/intention/emotion`|상대·행동 목적·감정의 맥락|
|`delivery_ko`, `direction_en`|그 줄에 맞춘 구체적 연기|
|`pace_wpm`, `energy`, `emphasis`, `*_pause*`|계획된 연기 목표. 실제 측정값·지원 API 인수라고 가정하지 않음|
|`instruct_prompt_en`|고정 정체성과 줄별 영어 지시를 합친 인계 문자열. 대사와 분리|
|`context_before/after`|앞뒤 본편의 이해를 위한 문맥. 읽지 않음|
|`proposal_dependency_note`|기준과 수정안의 조건. 음성 연기 텍스트에 섞지 않음|
|`synthesis_status`, `listening_review`|현재 모두 NOT_RUN. 실행 증거 없이 바꾸지 않음|

다음 문자열을 텍스트 앞에 이어붙여 합성하지 않는다: 화자 이름, 감정 라벨, 괄호 속 지시, ID, 전후 문맥, 한국어 설명. 원문에 없는 웃음·감탄사·이름을 추가하지 않는다. 쉼을 위한 간격과 대사의 말소리도 구분한다.

## 기준 본편과 제안을 섞지 않는 적용 규칙

JSON의 `story_jobs`128개는 기존 문구·화자 그대로다. 검토 제안 12묶음은 `CORRECTION_PROPOSALS.json`에 `PROPOSAL_NOT_APPLIED_TO_COMPLETED_PRODUCT`로 분리되어 있다. 검토 결과를 받았다는 이유만으로 완료본이 수정되었다고 기록하지 않는다.

### C01 · P01 손 펴기

- 권장 목표: **Open your hand!** / 기존: Open, close!
- 질문 NEW N005를 교체한다면: **Yoonsu, help him open his hand!**
- 제페토의 자기 손 시범 → 피노키오 반쯤 편 손 대기 → 입력 뒤 완전한 손 펴기를 함께 적용한다.
- `model_jobs`의 P01은 이 최종 제안 문구로 이미 작성해 두었다. `baseline_cue_text`는 기존 표현이고 `completed_product_change_applied=false`다. 기존 지도의 두 동작과 새 모델만 혼합하지 않는다.
- N005 교체 줄의 별도 연기는 C01의 `acting_variants_outside_139_default_jobs`에 있다.

### C02 · P04 첫 소개 순서

- 기준 N030: 피노키오 / Yoonsu, help me take a step!
- 교체 제안: 제페토 / **Yoonsu, help him take a step!**
- 질문 지도·음원·시선·카메라를 함께 바꾸고 모델 “One small step!”도 **GEPPETTO_A**로 교체한다.
- 기본 작업표의 P04 모델은 현재 기준 화자인 피노키오를 유지한다. 변경 시 C02의 전용 제페토 모델 변형을 사용한다. 두 모델을 연달아 읽거나 기본11개에 추가하여12개로 세지 않는다.
- 원본21개 정본 대사나 B08의 이름 소개는 바꾸지 않는다.

### C03/C04 · 모델과 입력

질문 끝 → 본편 정지 → 별도 모델1회(마이크 OFF) → 모델 종료 → 입력 열기 → 발화 시도 또는 보호자 터치 → 해당 반응1회 → 다음 본편 대사.

모델은 캐릭터의 시범이며 윤수의 답을 대신한 녹음이 아니다. 모델 재생 중 VAD를 켜지 않고 이전 재생 신호가 입력으로 다시 잡히지 않게 한다. 보호자는 모델을 건너뛰고 진행할 수 있다. 정확한 단어/발음 채점, 시간 초과의 자동 성공은 추가하지 않는다. 부분 발화와 몸짓을 존중하되 몸짓 자동인식 기능을 만들었다고 주장하지 않는다.

기존 B10-C02의390–400초 모델을 본편 회계에서 빼면 산술상443→433초다. 이는 실제 편집 결과가 아니다. 50컷 유지가 필요하면 모델 표시를 외부 상태로 분리하고 실제 서사 컷을 재배정한다. WAIT·반복·예시로 본편360초를 채우지 않는다.

## 기존 엔진과 연기 반영의 차이

현재 확보한 `scripts/s02_approved_voice_tts.py`는 `text`와 `audio_prompt_path`를 전달한다. 이 호출에 이번 `direction_en`이나 `instruct_prompt_en`을 읽는 경로는 없다. 따라서 지금 파일만 넘기고 기존 helper를 그대로 실행하면 새 연기가 전달된다고 보장할 수 없다.

실제 사용 중인 엔진·버전·지원 기능을 확인하고, 지원하는 연기 제어에 지시를 연결한다. 지원하지 않는 인수나 SSML을 지어내지 않는다. 지원이 부족하면 어떤 지시를 전달할 수 없는지 기록하고 동일 음색의 표현 샘플을 비교한다. 지시를 조용히 무시한 중립 낭독을 ‘연기 반영 완료’로 표시하지 않는다. 이번 요청으로 새 엔진·유료 서비스·외부 음성 업로드가 승인됐다고 가정하지 않는다.

## 실제 제작 시 확인할 것

- 피노키오는 각 줄의 발견·놀람·안도·수줍음·용기를 구분한다. 항상 높은 텐션으로 읽지 않는다.
- 제페토는 낮고 다정한 노년의 음색을 유지하며 상대에게 말한다. 질문을 시험 문제처럼 읽지 않는다.
- 요정은 맑고 안정적으로 말한다. 속삭임과 잔향으로 명료도를 덮지 않는다.
- 내레이터는 화면에 반응하는 이야기꾼이다. 캐릭터의 감정을 모두 같은 낭독 선율로 통일하지 않는다.
- 재합성할 경우 실제 WAV 길이·앞뒤 무음·대사 간 쉼을 측정해 컷을 배정한다. 기존109.25초 또는443초 계획에 억지로 빠르게 넣지 않는다.
- S01-U019의 상대는 **제페토**다. 1화에서 윤수와 이미 정식 첫 인사를 마친 연기가 되면 안 된다.
- S02 첫걸음의 성취→쿠션 안전 착지→즉각적 안심, P05의 his=Pino, 태엽 새의 선반 지지, P08/P09/I02의 역할을 함께 확인한다.

## 검토 데이터 검증 명령

프로젝트 루트 또는 패키지를 푼 루트에서:

```bash
python scripts/s01_s02_review_tools.py validate
```

검토 JSON을 의도적으로 편집해 사람용 대본/CSV를 다시 만들 때:

```bash
python scripts/s01_s02_review_tools.py build --report reviews/S01_S02_REVIEW_2026-11-23/VALIDATION.json
```

검사기는 기준 본편 원문과 화자를 지킨 검토 자료용이다. 나중에 실제 제작 입력으로 변경 제안을 적용하면 기준128개와 별도의 변경 이력을 사용해야 하며, 현재 보존 검사를 억지로 통과시키려고 기대값을 바꾸지 않는다. 합성·청취·렌더·플레이어 테스트를 실행하지 않는 도구다.

완료 기록에는 **자료/연기 지시 작성**, **실제 합성**, **실제 청취**, **완성 영상**, **기기 입력**, **아동 사용**을 각각 나누어 적는다. 이번 자료가 통과한 것은 첫 항목이다.
